# Повторяемые UI-тесты — EV Charging Tracker

Тест `UITests/ScenarioTests.swift` выполняет один фиксированный сценарий средствами XCTest/XCUIAutomation. Агент для запуска не нужен. Отдельная схема `EVChargingTrackerUI` не включает существующие unit-тесты; их запускают отдельно штатной командой проекта.

## Запуск

Нужны macOS, выбранный через `xcode-select` Xcode, Python 3 и установленный runtime iOS Simulator. Скрипт не требует сторонних Python-пакетов или RTK.

Из корня проекта:

```bash
python3 scripts/run_ui_scenario.py
```

По умолчанию: **iPhone 17 Pro Max, iOS 26.5, English, Light, системный размер Large**. Размер текста всегда задаётся явно, поэтому случайно оставленная настройка Accessibility XXXL не влияет на следующий прогон.

```bash
# Русский интерфейс и тёмная тема
python3 scripts/run_ui_scenario.py --language ru --appearance dark

# Крупнейший размер Dynamic Type
python3 scripts/run_ui_scenario.py --text-size accessibility-extra-extra-extra-large

# iPhone Duo: нужен установленный совместимый runtime
python3 scripts/run_ui_scenario.py --device 'iPhone Duo' --runtime 27.1

# Проверить параметры без сборки и создания симулятора
python3 scripts/run_ui_scenario.py --dry-run
```

Допустимые значения параметров показывает `--help`. Совместимость модели и runtime проверяет `simctl`; скрипт не скачивает runtime. Профили Duo и Accessibility XXXL требуют отдельного прогона и не считаются проверенными по результату обычного Pro Max.

## Сценарий create-edit-cancel

1. Запустить чистую установку, выбрать язык, перейти на вводный экран и пропустить остальные страницы онбординга.
2. Открыть форму и создать зарядку через обычный интерфейс. Энергия: 40 кВт⋅ч, пробег: 10000, стоимость: 5.20, автомобиль: `UI regression EV`, заметка: `UI regression charge`.
3. Проверить появление экранной клавиатуры, сохранить запись и найти её в списке.
4. Открыть редактирование свайпом, изменить значение, отменить и повторно открыть запись: исходное значение должно сохраниться.
5. Перезапустить приложение и проверить сохранённую запись снова.

Скрипт не заполняет SQLite напрямую и не включает скрытые тестовые режимы приложения. Элементы находятся по стабильным accessibility identifiers; вкладки выбираются по их порядку в приложении.

## Результаты и изоляция

Каждый прогон пишет отдельный каталог `ui-test-results/<UTC-дата>-<id>/`:

- `run.json` — точные параметры, итоговый статус, UUID созданного симулятора и результат его удаления;
- `Results.xcresult` — отчёт Xcode, открываемый в Xcode;
- `attachments/` — экспортированные снимки контрольных точек и финальная иерархия интерфейса; `manifest.json` связывает UUID файлов с именами снимков (`suggestedHumanReadableName`);
- `build.log`, `test.log`, `export.log` — диагностические логи;
- `summary.json` — сводка успешного запуска; при ранней ошибке файл может отсутствовать.

Код завершения **0** означает один успешно пройденный UI-тест без пропусков и успешный экспорт артефактов. Ошибки сборки, теста, экспорта или удаления симулятора дают ненулевой код. Кеш сборки находится в `.ui-test-cache/`; одновременные запуски в одном репозитории запрещены блокировкой.

Скрипт создаёт собственный временный симулятор, не очищает существующие устройства и удаляет только созданный им UUID при обычном завершении, ошибке или Ctrl+C. Принудительное завершение процесса или выключение Mac может оставить этот симулятор; его UUID записан в выводе запуска.

## Что проверяется автоматически

Прохождение онбординга, доступность задействованных кнопок, ввод с клавиатуры, создание записи, отмена редактирования и сохранение после перезапуска. Проверки типографики, контраста и каждого экрана приложения этим сценарием не покрыты. Снимки сохраняются для визуальной проверки; сравнения с эталонными изображениями пока нет.

Чтобы добавить визуальную проверку агентом, задайте ему фиксированный порядок: запустить скрипт с указанными параметрами; прочитать `run.json`; проверить снимки `01-language`, `02-introduction`, `03-create-keyboard`, `04-saved`, `05-cancel-preserved` на обрезанный текст, перекрытия и недоступные кнопки; выдать PASS/FAIL отдельно для каждого снимка со ссылкой на доказательство. Отсутствующий снимок или непройденный шаг — FAIL. Дополнительные действия агента не заменяют шаги сценария.

## Проверка самого скрипта

```bash
python3 -m unittest discover -s scripts -p test_ui_scenario_runner.py -v
```

Проверяются передача языка в `.xctestrun`, отклонение неверного профиля и удаление только собственного симулятора при ошибке сборки.
